# ٢) كشف حساب الزبون — عربية مقطّعة + تاريخ الأصناف

**الطلب:** (أ) كشف الحساب يُطبع بحروف عربية **مقطّعة** بينما الفاتورة العادية سليمة.
(ب) جدول «الأصناف التي أخذها» لا يُظهر **تاريخ ووقت** أخذ الصنف.

## 🚨 السبب الجذري (مُثبَت بالتشغيل لا بالادّعاء)

حزمة `pdf` (المُثبَّتة **3.11.3**) لا تُشكّل العربية إلا بشرط الاتجاه — من
`pdf/src/widgets/text.dart`:

```dart
final _textDirection = textDirection ?? Directionality.of(context);
...
useArabic && _textDirection == TextDirection.rtl ? arabic.convert(text)
: useBidi  && _textDirection == TextDirection.rtl ? bidi.logicalToVisual(text)
: text
```

و`pdf/src/pdf/options.dart`:
```dart
const bool useBidi   = bool.fromEnvironment('use_bidi',   defaultValue: true);
const bool useArabic = bool.fromEnvironment('use_arabic', defaultValue: !useBidi);
```
⇒ الافتراضي `useArabic = false` و`useBidi = true`، **والفرعان كلاهما مشروط بـ`rtl`**.
بلا `textDirection` يُرسم النصّ بترتيبه المنطقي ⇒ حروف مقطّعة/معكوسة.
(ولا يوجد `--dart-define=use_arabic` في المشروع إطلاقًا — تحقّقتُ بالبحث الشامل.)

**الدليل التجريبي:** `tool/_probe_arabic_pdf.dart` وَلَّد ملفين من نفس الخط والنص،
واحدًا بلا اتجاه والآخر بـ`rtl`، ثم رُسِما بـPyMuPDF:

| | النتيجة |
|---|---|
| بلا `textDirection` | `ددسمل ا تاعفدلا مذلا فانصألا ةذوخأملا` — مقطّعة ومعكوسة |
| `textDirection: rtl` | `المسدد الدفعات الذمم الأصناف المأخوذة كشف حساب الزبون` — سليمة موصولة |

**الفرق في الكود:** `generatePdfData` (الفاتورة) تضبط `textDirection: pw.TextDirection.rtl`
على **22 نصًّا**؛ أما `generateCustomerStatementPdf` فكانت **بلا أي ضبط** (0).

## ✅ حلّ «العنوان اليتيم» — تصحيح استنتاج سابق في هذا الملف
